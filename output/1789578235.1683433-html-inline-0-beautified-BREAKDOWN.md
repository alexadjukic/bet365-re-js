# Breakdown: `1789578235.1683433-html-inline-0-beautified.js`

This is the bet365.rs **bootstrap/loader script** — inline JS embedded in the page `<head>`/`<body>`
that runs before the "real" application. Its job is: read config, open sockets, fetch the
JS/CSS application bundle ("Blob"), then hand off to the actual site launcher
(`SiteLauncherModule.InitWeb` / `AppLauncherModule.InitApp`).

Variable names are minified (single letters like `f`, `R`, `S`, `x`, `$`), so this breakdown
maps each one to its purpose.

---

## 1. Top-level IIFE (lines 1–3) — Asian-locale CSS hook
```js
if ("WebkitAppearance" in style && ["zh","zh-TW",...,"ja","ko"].indexOf(navigator.language) > -1)
  html.className += " asia-browser";
```
Detects WebKit browsers with a CJK `navigator.language` and tags `<html>` with `asia-browser`
so CSS can apply CJK-specific font/layout rules.

## 2. `Modernizr = {}` (line 4)
Empty placeholder object — feature-detection results get populated into this later by another
bundle; unused directly in this file.

## 3. `ns_weblib_util.WebsiteConfig` (lines 5–291)
The central **site configuration object**, injected server-side per request. Key fields:
- `SERVER_TIME` — Unix timestamp from the server (for clock-skew correction).
- `BLOB_LOCATION` / `BLOB_PATH` — where the compiled JS/CSS "Blob" bundles are served from.
- `SITE_CONFIG_LOCATION` — endpoint for the sports/site config JSON (`/defaultapi/sports-configuration`).
- `MANIFEST_CONFIG_LOCATION(S)` — endpoint(s) for the module manifest (maps module name → version/flags).
- `COUNTRY_LOCALE` / `STATE_LOCALE` — user locale, e.g. `"RS"` (Serbia).
- `CLIENT_ERROR_LOCATION` — where boot errors get POSTed (`clienterrors.365lpodds.com`).
- `CONNECTION_DETAILS` / `PRIVATE_CONNECTION_DETAILS` — WebSocket hosts for live odds (`zap` protocol),
  one public, one "private" (personalised) channel.
- `CONTENT_CONNECTION_DETAILS` — a scores/content coordinator host.
- `GRCK` / `GRCEK` — Google reCAPTCHA site keys.
- `SERVICE_RULES_LOCATION` — endpoint for routing/service rules.
- `CW` — "Custom Widget" list — extra scripts loaded after the main blob (module `cwc`, version `738`).
- `SITE_PRELOAD` / `NATIVE_PRELOAD` — **ordered lists of modules** to preload for web vs. native-app
  contexts. Each entry: `m` (module name), `v` (version), `f` (a bitmask flag controlling extra
  suffixes — App variant / "S" / "L" build), `c` (load condition: `"y"`=yes, `"c"`=conditional).
- `RBM` — "Report Boot Metrics" flag, gates XHR timing collection throughout the file.

### Betslip WebView health-check (lines 300–317)
If the URL hash is exactly `#/BS/` (native app's embedded betslip webview) and `BroadcastChannel`
is supported, it:
- Opens a `betslip_webview_health` channel and replies `pong_boot` to `ping` messages (lets the
  native shell verify the webview booted).
- Redefines `appErrorReport`/`appBetslipInfoLogAdd` to push into an in-memory log array and
  broadcast it (`pong_inforeport:...`) to the native app after a 1s debounce.
- Installs a `window.onerror` handler that formats and reports uncaught errors through this channel.

### `GetCookieAttributeValue(name, subKey)` (lines 319–336)
Parses `document.cookie`, finds a cookie by `name`, and optionally digs into a `&`-delimited
sub-key/value list inside that cookie's value (bet365 packs multiple values into one cookie,
e.g. `aps03` holds language/country/tax-table flags). Returns URI-decoded value or `null`.

### `encodeAsContentFilter64(e)` (lines 338–341)
A custom base-4096 → 2-digit encoder using the `base64Digits` alphabet (below). Used later to
encode country/zone/state IDs into short tokens (`COUNTRY_GROUP_ID_B64`, etc.) sent to content
filtering endpoints.

### `base64Digits` (line 342)
`["0"…"9","A"…"Z","a"…"z","%2b","/"]` — a URL-safe base64-like digit table (64 entries) used by
`encodeAsContentFilter64`.

## 5. Main IIFE — the `boot` module: `(f => { ... })(boot = boot || {})` (lines 342–1238)

Everything below lives in one closure, exposed publicly as the global `boot` object (`f` inside
the closure). This is the actual bootstrapper logic.

### 5.1 Boot metrics buffer
```js
let t = [], r = null;
function _(e) { t.push(e); if (r) try { r() } catch {} }
f.addBootMetric = _;
f.fetchAndClearBootMetrics = () => { var e = t.slice(); t = []; return e };
f.setBootMetricsAvailableCallback = e => { r = e };
```
A simple pub/sub queue: internal code calls `_({...})` to push a metric event (e.g. blob load
time, service-rules duration); external code drains it via `fetchAndClearBootMetrics`, optionally
notified via a registered callback.

### 5.2 XHR timing aggregation — "bxhr" (`u`, `d`, `c()`)
```js
let u = [], d = new Set(["bxhr_b","bxhr_c","bxhr_h"]), q = false;
function c() { ... }
```
Every XHR fired later in the file (blob, config, homepage, manifest, personalisation requests)
registers `loadstart`/`loadend` listeners that push `{purpose, duration}` into `u`. Once `RBM` is
on and all "core" purposes (`bxhr_b`=blob, `bxhr_c`=config, `bxhr_h`=homepage; more added
dynamically: `bxhr_s`=service-rules, `bxhr_m`=manifest, `bxhr_p`=personalisation) have reported,
`c()` bundles the durations and calls `_()` to emit a `"bxhr"` boot metric once (`queueFullJSON`).

### 5.3 Global error handling (lines 381–394)
Three branches depending on environment:
1. **Existing `window.onerror`** (already set by the betslip webview block above) → saved as
   `f.betslipWebViewGlobalErrorHandler`.
2. **iOS app** (`window.webkit.messageHandlers["ns_appconsolemodule_app.reportJSError"]` present)
   → installs `f.iosAppGlobalErrorHandler`, forwards errors to native iOS via message handler,
   including the last blob fragment context from `ee()`.
3. **Plain web** → generic handler that calls `F("global", ...)` (see §5.19, error reporting API).

### 5.4 Logging helpers
- `C(...)` — pretty console.log with bet365 styling (`color:#222; background-color:#4acfa5`),
  falls back to plain `console.log`; also appends to history array `W`.
- `g(t)` — routes through `ns_gen5_util.InfoReporter.Trace("BLOB", t)` if the main app framework
  is already loaded, else falls back to `C(t)`. Used for retry/diagnostic messages.
- `H` — user's language from the `aps03` cookie.
- `f.BLOB_URL` — base URL for blob fetches: `BLOB_LOCATION + lang + "," + SITE_NAME + ","`.

### 5.5 Blob load mode (`P`, `l`, `f.BlobLoadingMode`)
```js
let l, P = (enum BlobLoadMode {BatchedModuleUrls=0, SingleModuleUrls=1});
f.BlobLoadingMode = (?sfb=1 in URL) || (SFBP>0 && no sfb=0) ? SingleModuleUrls : BatchedModuleUrls;
```
Decides whether all modules are requested as **one combined URL** (batched, default) or as
**separate per-module requests** (single), controllable via `?sfb=1`/`?sfb=0` query param or the
`SFBP` config rollout percentage.

### 5.6 Boot readiness state
```js
let V=0, m=false, v={}, E={isComplete: window.testharness, onComplete: void 0};
```
- `m` — manifest loaded.
- `v` — accumulator for multi-part manifests.
- `E` — "service rules" completion gate (`isComplete`/`onComplete`).
- (later) `A` — "rll" priority module loaded, `j` — DOM body ready, `P` — site config processed.
These five booleans/flags are the **readiness gate** checked in `x()` (§5.16).

### 5.7 Service Rules fetch (lines 436–479, function `n`/`e`)
If not already complete (`!E.isComplete`), fires an XHR to `SERVICE_RULES_LOCATION`, retries up
to 5 times with a 15s delay between attempts (`G`/`F` on final failure), parses the JSON response
into `ns_weblib_util.WebsiteConfig.SERVICE_RULES`, marks `E.isComplete = true`, invokes
`E.onComplete`, then calls `x()` to re-check readiness. On a `403`, tints the preloader spinner
border red-ish (`#65737E`) as a subtle visual error cue.

### 5.8 App-request / native-app detection
```js
p = () => userAgent has "Gen6" && not "bet365/9" && not "bet365App";
let L = androidMessageHandlers.postMessage exists && p();
f.isAppRequest = (iOS webkit "pagerender_end" handler present) || p() || L;
```
Determines whether the page is running inside the **native app's embedded webview** (Android or
iOS "Gen6" hybrid shell) vs. a normal browser tab. Drives many branches later (timeouts, native
bridge calls instead of XHR, etc.).

### 5.9 `R(url, onComplete, meta)` — Blob loader (batched mode) (lines 493–590)
Fetches a combined multi-module "Blob" bundle via XHR:
- Registers timing listeners (`bxhr_b`) if `RBM`.
- Per-request retry state tracked in `y[sequenceId]` (`expectedFiles`, `retryAttempt`);
  timeout is `21s` (or `26s` for Android app) × `1.4^retryAttempt` (exponential backoff).
- On success (`status===200`), parses the custom Blob wire format: response text is a sequence of
  chunks, each starting with a 1-char **file-type code** (`charCodeAt(0)`) followed by content.
  Type `4` = JavaScript (injected as a `<script>` in `<head>`), type `5` = CSS (injected via
  `te()` as a `<style>`).
- Verifies the chunk count matches `expectedFiles`; on mismatch calls `K()` (reports + retries).
- On success, emits a `"bootBlobMetrics"` metric (file count, size, parse time) via `_()` and
  `appBetslipInfoLogAdd`, then invokes the completion callback and processes any queued
  out-of-order responses (`T` array, for `sequenceId` ordering via global counter `X`).
- Also pings `Locator.validationManager.processValidationCycleNow()` if that module is loaded (a
  DOM/state validation hook from another bundle).

### 5.10 `S(module, batchNumber, url)` — Blob loader (single/per-module mode) (lines 592–711)
Same retry/timeout/backoff machinery as `R`, but for **one module's** own request within a batch
group tracked in `I` (array of in-flight batches, each with a list of module `requests`). Once
all modules in a batch report loaded (`t.complete`), the front of `I` is processed: injects each
module's script/style chunks in order, reports aggregate metrics, calls the batch's
`completionHandler`, and advances to the next queued batch.

### 5.11 `Q(...)` / `K(...)` — Blob error/retry helpers (lines 713–743)
- `Q` — generic HTTP-error retry path for `R()` (5 attempts max, then reports via `F`).
- `K` — "unexpected file count" retry path for `R()` (logs expected vs actual chunk sizes, retries).

### 5.12 `ee(errorMessage)` — Syntax-error diagnostics helper (lines 748–750)
If the last global error looks like a `SyntaxError` (and not JSON-related), returns a formatted
dump of the last-loaded blob fragment's metadata (`O`: url, fileIndex, sequenceId, a truncated
content fragment) — attached to error reports so a broken/truncated blob chunk is traceable.

### 5.13 `te(cssText, headEl)` — inject `<style>` (lines 752–755)
Creates a `<style>` element and sets its content (with an `styleSheet.cssText` fallback for old
IE), appends to `<head>`.

### 5.14 `se(moduleName, manifestEntry)` — Blob module path builder (§ near line 898)
Computes the URL path segment and expected file count for a module, based on its manifest version
and bitflags:
- Base: `moduleName/version/`.
- If app-request and flag bit `4` set → recursively resolves a `-App` variant module first and
  prefixes it (`|`-joined).
- Flag bit `2` → appends `S` suffix (adds 1 file) — likely "Sass/Style" bundle.
- Flag bit `1` → appends `L` suffix (adds 1 file) — likely "Locale" bundle.
Returns `{blobModule, expectedFiles}`.

### 5.15 `M()` — high-res timer (performance.now with Date.now fallback).

### 5.16 `x()` — Boot readiness gate (lines 1063–1070)
```js
if (P && m && A && j && E.isComplete) { ...launch... }
```
Once site-config (`P`), manifest (`m`), the priority `rll` module (`A`), DOM ready (`j`), and
service rules (`E.isComplete`) are **all** true: marks a perf timestamp (`zz_ebs`), then calls
`AppLauncherModule.InitApp(a)` (native app) or `SiteLauncherModule.InitWeb(b, a)` (web) — `a` is
the list of already-loaded module names, `b` is the map of opened WebSocket connections. This is
called repeatedly from every async completion handler until all conditions are satisfied.

### 5.17 `$()` — Blob-complete → DOM-ready gate (lines 1059–1062)
Called when the main blob batch finishes loading. If in replay mode, kicks off
`ReplayLogger.BeginPlayback()`. Waits (polls every 1ms) until `document.body` exists, then sets
`j = true` and calls `x()`.

### 5.18 Manifest loading — `ce()` / `N()` (lines 1109–1157)
`ce(url, retryCount)` fetches the module manifest (name→version/flags map) via XHR:
- Supports **multi-manifest merging**: if more than one `MANIFEST_CONFIG_LOCATION` is configured,
  merges each response's `m` (module map) into a shared `_websiteManifest`, tracking per-source
  versions in `_websiteManifest.vi`.
- On parse error or non-200, retries via `N()` up to 5 times (linear retry counter, not
  exponential), then reports via `F`.
- On the last expected manifest response (`++V == MANIFEST_CONFIG_LOCATIONS.length`), sets `m =
  true` and calls `x()`.

### 5.19 Site/sports config loading — `fe()` / `be()` / `we()` (lines 1072–1194)
- `fe(retryCount)` — fetches `SITE_CONFIG_LOCATION` (`/defaultapi/sports-configuration`). In
  **replay mode** (`sessionStorage.replay` present), skips the network call and replays a stored
  response instead. Appends the URL hash as a `pd=` query param (deep-link routing context) and a
  retry counter `rt=`/cache-buster `rn=` on retries. Exponential backoff (`15s × 1.4^n`), 5 max
  attempts via `be()`.
- `we(responseText, cookieLang)` — the config processor, run once the config XHR succeeds:
  - Handles server-side redirects (`"redirectto:"` prefix).
  - Verifies the cookie language still matches what was requested (else forces a full page
    reload — avoids serving mismatched-locale config).
  - Parses JSON into `t`; computes the **React Router A/B rollout** — reads
    `flashvars.REACT_ROUTER_PERCENTAGE` (comma-separated web/app percentages), rolls a random
    number, and sets `flashvars.REACT_ROUTER` true/false; also resolves
    `flashvars.REACT_PAGE_EXCLUSIONS` from a `?rp=` query override or config default.
  - For app requests: forces `NEW_NATIVE_NAVIGATION`/`PAGEDATA_CARD_NAVIGATION` flags and forwards
    the whole config to native via `ie("sportsconfig", ...)` (queued until service-rules complete).
  - Sets `window.flashvars = t.flashvars` (the global feature-flag/config bag most other bundles
    read from).
  - Computes three `*_B64` content-filter tokens (`COUNTRY_GROUP_ID_B64`, `COUNTRY_ID_B64`,
    `COUNTRY_STATE_ID_B64`) via `encodeAsContentFilter64`, offsetting IDs by fixed bases
    (`1024+`, `2048+`) — likely namespacing IDs into disjoint ranges for a shared content-filter ID space.
  - First-load only (`oe` flag): caches zone/currency/filter-mode/tailoring preferences into
    `localStorage["ns_podloadermodule_util.PreferenceSettings"]` and kicks off `re()`
    (homepage data prefetch).
  - Merges `t.ns_weblib_util.WebsiteConfig` into the live `WebsiteConfig` object (server can patch
    config values post-load).
  - Calls `ne()` (personalisation, below), sets `P = true`, calls `x()`.

### 5.20 Personalisation — `ne()` (lines 834–885)
Checks for a `pers` cookie + country/language cookies, and gates on an eligibility check:
explicit `?pers=1`/`?pers=0` query override, else an `EXPERIMENTAL_FEATURES` local-storage flag,
else an A/B experiment flag `SUI_PERS_HOME_CLASS_RIBBON` parsed out of
`flashvars.ABEXPERIMENTS` JSON, else falls through to `flashvars.PERSONALISATION_ENABLED`.
If eligible: fetches `/personalisationapi/summary?id=<persId>` with a timeout
(`PERSONALISATION_TIMEOUT` or 30s default) via `AbortController` + `fetch()`, stores the result
on `f.personalisationData` and calls `f.personalisationDataReceived()`. Swallows
`QuotaExceededError` from any downstream storage write; reports other errors via `F`.

### 5.21 Homepage data prefetch — `re()` (lines 762–832)
Prefetches homepage "pods" content (`/pullpodapi/gethomepagepods`) ahead of the app taking over,
so the homepage renders instantly:
- In replay mode, short-circuits with empty data.
- Reads zone/currency/filter-mode/country-state from `window.flashvars` or the cached
  `PreferenceSettings` localStorage blob (fallback for returning visitors before config loads).
- Builds a query string with a `cgid`/`ctid`/`csid` filter chain based on `EXCLUSION_LEVEL` (`-1`
  = none, `1`/`2`/`3` = increasingly specific geo filters), plus a tailoring-type param derived
  from `aps03` cookie flags (`cf`, `hd`, `tt`) and an optional session `pcode`.
- For native app: sends the request spec to the native shell to prefetch/subscribe instead of
  XHR-ing directly (`ie("...pull_subscribe", ...)`).
- For web: fires the XHR itself, records the response for replay logging
  (`ReplayLogger.RecordPullRequest`), and stores it on `f.homepageData`.

### 5.22 Native bridge — `ie(method, data)` (lines 887–896)
Thin wrapper that posts a message to the native app shell: Android via
`window.androidMessageHandlers.postMessage`, iOS via
`window.webkit.messageHandlers[method].postMessage`. Wrapped in try/catch reporting via `F`.

### 5.23 `f.getLocale()` (lines 911–917)
Returns `{countryLocale, stateLocale}`, preferring `WebsiteConfig`'s values, falling back to
`window.UICoreLib.getLocaleValue(...)` if available. Also persists the current session's `pcode`
cookie value into `sessionStorage` for reuse across the boot flow.

### 5.24 `f.ReportSiteLoadMetrics()` (lines 918–935)
One-shot (guarded by `le === -1`) timer that reports total site-load duration since `de()` was
called, as a `"sls"` (single-module) or `"slb"` (batched) boot metric.

### 5.25 Batched multi-module requests — `f.RequestBlobbModules` / `B()` (lines 936–971)
Public API (`f.RequestBlobbModules(moduleList, completionHandler)`) for requesting a batch of
modules via the per-module (`S()`) path; assigns a `batchNumber`, pushes tracking state into `I`,
and fires one `S()` XHR per module. `B(module, batchNumber)` looks up a module's tracking record
by batch+name for retry bookkeeping.

### 5.26 Legacy-browser detection — `p()` (lines 972–985, reused var name)
Returns true for **unsupported old browsers**: Chrome ≤49, Firefox ≤31, Safari (`Version/` token)
≤10, or any MSIE/Trident — used to redirect away (see next section). Note: not iPhone/iPad Safari
(WebKit version string differs there, so it's excluded from the Safari check).

### 5.27 Main boot sequence (lines 986–1057)
This is the **entry point logic** that runs synchronously when the closure executes:
1. **Unsupported browser redirect**: if not an app request and `p()` (old browser) is true,
   redirects to a static "Unsupported Browser" HTML page (`MSIE 5/6/7` gets a v3-specific IE
   page, everything else gets a generic v3 page).
2. Otherwise:
   - Loads the manifest if `_websiteManifest` isn't already present (via `ce()` for each
     `MANIFEST_CONFIG_LOCATIONS` entry), else marks `m = true` immediately (manifest was inlined
     server-side).
   - Picks the preload list: `SITE_PRELOAD`/`_websiteManifest.sp` for web, or
     `NATIVE_PRELOAD`/`_websiteManifest.np` for app requests; for app requests also sets
     `WebsiteConfig.DOMAIN` and marks perf `zz_hwc`, and prepares `p()` to forward the config to
     native once service rules complete.
   - **Not** app / not replay: opens the two WebSockets described earlier
     (`CONNECTION_DETAILS[0]` and `PRIVATE_CONNECTION_DETAILS[0]`, both `zap` protocol v2/v1
     respectively), buffering their `open`/`message` events into `b[host]` so the launcher can
     pick them up later without racing the connection.
   - **Batched mode**: first requests the priority `rll` module alone via `R()` (sets `A = true`
     on completion) — likely a "render loop library" or similar critical-path module loaded ahead
     of everything else; then builds one combined blob URL for all remaining
     `y`/`c`(app)/`c`(conditional)-flagged preload modules plus any `CW` custom-widget entries,
     and fires that combined request via `R(url, $, {...})`.
   - **Single mode**: skips the combined-URL step (`A = true` immediately); presumably per-module
     requests are issued elsewhere via `RequestBlobbModules`.
   - Kicks off homepage prefetch `re()` unless the URL hash already targets homepage (`#/HO/`) or
     is empty (avoids double-fetching if the router will fetch it itself).
   - Calls `fe()` to start the site/sports-config fetch.

### 5.28 Error reporting API — `F(funcname, message, metadata, stack)` (lines 1196–1218)
POSTs a structured error report to `CLIENT_ERROR_LOCATION`
(`clienterrors.365lpodds.com/api/1/clienterrors/batch`), gated by
`WebsiteConfig.REPORT_BOOT_ERRORS`. Payload includes: summary, filename `"boot"`, function name,
message, stack (or last-blob-fragment info from `ee()` as fallback), current URL, the accumulated
console/trace history (`W`), language, `pstk` session cookie, manifest version, and a Unix
timestamp. This is the **catch-all telemetry sink** referenced by nearly every error branch above.

### 5.29 Final wiring (lines 1219–1238)
- `f.initialFilesLoaded()` — after the main blob's scripts have executed, sequentially loads any
  `CW` (custom widget) scripts as real `<script src=...>` tags (not injected via blob text), and
  once the last one loads, calls `$()` to continue the readiness chain. If there are no `CW`
  entries, calls `$()` immediately.
- `f.initialBlobLoaded = $` — public alias.
- Stubs out a fake test harness (`window.ns_testharness`, `ns_testharness_events`,
  `ns_testharness_ui`, `StubLookup`, `Harness_main`) — placeholder classes/objects so code that
  references the test harness API doesn't throw when the real harness bundle isn't loaded (only
  loaded in QA/testing builds).
- `k = Date.now() + Math.random()` — a cache-busting token reused in config retry URLs (`&rn=`).
- Removes the inline `<script id="bootjs">`/`#bootsjs` tag itself from the DOM once boot logic has
  run, to keep the DOM clean after handing off to the app.

## High-level summary

This file is bet365's **pre-app bootstrap loader**:
1. Detects platform (native app webview vs. browser, old/unsupported browsers → redirect).
2. Loads the module **manifest** and **service rules**.
3. Fetches the **sports/site configuration** (feature flags, A/B experiment assignment for React
   Router migration, locale, content-filter tokens) and personalisation data.
4. Opens **WebSocket** connections for live odds (public + "private"/personalised channel).
5. Downloads the app's JS/CSS as a custom **"Blob" bundle format**, either as one combined
   batched request or per-module requests, injecting each chunk as `<script>`/`<style>` tags,
   with exponential-backoff retry logic throughout.
6. Prefetches homepage content in parallel so first paint is instant.
7. Collects fine-grained **timing/metrics and error telemetry** at every step, reporting failures
   to a dedicated client-error collection endpoint.
8. Once config, manifest, priority module, DOM, and service rules are all ready, hands off to
   `SiteLauncherModule.InitWeb` (browser) or `AppLauncherModule.InitApp` (native app webview).
